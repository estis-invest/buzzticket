# WELCOME TO BUZZTICKET

This project is a self-hosted **multi-module** ticket management system and was intended as 
my first attempt at advanced software architecture focused on *Tactical Domain Driven Design* (*DDD*), *Hexagonal Architecture* and 
*Onion Architecture*.


## 📋 Requirements & Tech Stack Summary

### Runtime & Environment
* **Java 25:** Requires Java 25 SDK (utilizing dynamic agent loading and modern JVM features).
* **Docker Desktop / Engine:** Required locally to support containerized integration testing via Testcontainers.
* **Apache Maven 3.9+:** Multi-module build management.
* **PostgreSQL:** Relational database storage managed via automated Flyway schema migrations.
* **POSIX Utilities (OpenSSL, Bash, sed):** Required for automated environment secret and RSA key pair generation scripts (`openssl`, `bash`, `sed`, `touch`, `chmod`).

### Version Control & Quality Workflow
* **Lazygit:** Terminal UI for Git version control management.
* **CodeRabbit AI:** AI-driven automated pull request code reviewer.

### Frameworks & Core Libraries
* **Spring Boot 4.0:** Base framework providing web REST APIs, Spring Security (OAuth2 / JWT Resource Server), and Spring Data JPA.
* **Nimbus JOSE JWT:** Cryptographic handling for RSA-signed token generation and verification.
* **Flyway:** Versioned database migration management.

### Testing Tools & Quality Assurance
* **JUnit 5:** Primary test framework for unit and integration testing.
* **Testcontainers:** Spins up real PostgreSQL instances inside temporary Docker containers for true-to-production database integration tests.
* **ArchUnit:** Enforces domain isolation and Hexagonal Architecture package boundary rules through automated unit tests.
* **AssertJ & Mockito:** Fluent assertions and behavior mocking for application/domain use-case tests.
* **Awaitility:** Asynchronous test verification utility.

## 🏗️ Setup and Installation
The section has the installation and setup steps to run Buzzticket locally.

### Step 1: Clone Repository
```shell
git clone https://github.com/estis-invest/buzzticket
```

### Step 2: Environment Configuration

* Change directory
```shell
cd buzzticket
```
* Copy env-example to .env file
```shell
cp -f ./env-example .env
```
* Open the .env fill out the necessary fields 


### Step 3: Generate HMAC Secret
HMAC Secret for token invitation to populate `STAFF_INVITE_HMAC_SECRET=` can be generated by running:

* File named: `generate-invite-token-secret.sh`

#### Execution of file and HMAC secret generation
```shell
chmod +x generate-invite-token-secret.sh
./generate-invite-token-secret.sh
```

### Step 4: Generate RSA Key Pair
Generate RSA key pair by running the file: 

* File named: `generate-jwt-keys.sh` 

#### Execution of file and RSA pair generation

```shell
chmod +x generate-jwt-keys.sh
./generate-jwt-keys.sh
```

The command generates a new directory called keys: 

```shell
ls keys
jwt-private.pem jwt-public.pem
```
> Note jwt-private.pem is the private key and should be kept **SECRET** 


### Step 5: Start Infrastructure Containers
Run docker-compose to create containerized env:

```shell
docker-compose up -d
```

> Note that all fields in the .env must be populated to work


### Step 6 First Run of Buzzticket (Critical Step)
Run Buzzticket by executing the run file called: 

* File named: `run.sh` 

```shell
chmod +x run.sh
./run.sh
```

> Once running, access application at configured port or the default `http://localhost:8080`.

### Step 7 Demo & Verification (Optional)

> Note that the steps description for populating db with sample data requires all previous steps to be completed Step 1 through Step 6.

To populate the database with sample data please follow these steps in [seed/README-SEED.md](seed/README-SEED.md)

## Buzzticket - API Endpoints
List of current available API endpoints

### 🌐 Public Onboarding & Auth Endpoints

> **Auth:** None (Publicly Accessible)

| Method | Endpoint                           | Description                                                        |
|:-------|:-----------------------------------|:-------------------------------------------------------------------|
| `POST` | `/public/v1/company-registration`  | Registers a new company (creates initial admin user and partner)   |
| `POST` | `/public/signup`                   | Registers a new customer account                                   |
| `POST` | `/public/staff/invitations/accept` | Accepts a staff invite using a raw token and registers the account |
| `POST` | `/auth/login`                      | Authenticates user credentials and returns a JWT access token      |
| `GET`  | `/.well-known/**`                  | Exposes public JWKS metadata for verifying RSA-signed JWT tokens   |


### 🔑 Authentication & Session (`/auth/*`)

> **Auth:** Bearer Token (JWT)

| Method | Endpoint        | Authorization | Description                                          |
|:-------|:----------------|:--------------|:-----------------------------------------------------|
| `POST` | `/auth/refresh` | Authenticated | Refreshes the session and returns a new access token |
| `GET`  | `/auth/me`      | Authenticated | Retrieves profile information for the current user   |

### 🏢 Partner Endpoints (`/api/v1/partners`)

> **Auth:** Bearer Token (JWT)

| Method   | Endpoint                           | Authorization                  | Description                      |
|:---------|:-----------------------------------|:-------------------------------|:---------------------------------|
| `POST`   | `/api/v1/partners`                 | `ADMIN`                        | Register a new partner           |
| `GET`    | `/api/v1/partners`                 | `ADMIN`, `SUPPORT`, `CUSTOMER` | Retrieve all registered partners |
| `GET`    | `/api/v1/partners/{id}`            | `ADMIN`, `SUPPORT`, `CUSTOMER` | Retrieve partner details by ID   |
| `PATCH`  | `/api/v1/partners/{id}`            | `ADMIN`                        | Update partner details           |
| `PATCH`  | `/api/v1/partners/{id}/activate`   | `ADMIN`                        | Activate a partner account       |
| `PATCH`  | `/api/v1/partners/{id}/deactivate` | `ADMIN`                        | Deactivate a partner account     |
| `DELETE` | `/api/v1/partners/{id}`            | `ADMIN`                        | Remove a partner                 |


### 👥 Staff Management Endpoints (`/api/v1/staff`)

> **Auth:** Bearer Token (JWT)

| Method  | Endpoint                                | Authorization | Description                                                     |
|:--------|:----------------------------------------|:--------------|:----------------------------------------------------------------|
| `POST`  | `/api/v1/staff/invitations`             | `ADMIN`       | Create and send a new staff invitation                          |
| `GET`   | `/api/v1/staff/invitations`             | `ADMIN`       | Retrieve staff invitations filtered by `status` query parameter |
| `GET`   | `/api/v1/staff/invitations/{id}`        | `ADMIN`       | Retrieve staff invitation details by ID                         |
| `GET`   | `/api/v1/staff/invitations/exists`      | `ADMIN`       | Check if a pending invitation exists for a given `inviteeEmail` |
| `PATCH` | `/api/v1/staff/invitations/{id}/cancel` | `ADMIN`       | Cancel a staff invitation                                       |


### 🎟️ Ticket Endpoints (`/api/v1/tickets`)

> **Auth:** Bearer Token (JWT)

| Method   | Endpoint                                        | Authorization      | Description                            |
|:---------|:------------------------------------------------|:-------------------|:---------------------------------------|
| `POST`   | `/api/v1/tickets`                               | Authenticated      | Register a new ticket                  |
| `GET`    | `/api/v1/tickets`                               | Authenticated      | Retrieve reported tickets              |
| `GET`    | `/api/v1/tickets/{id}`                          | Authenticated      | Retrieve reported ticket details by ID |
| `POST`   | `/api/v1/tickets/{id}/assignments`              | `ADMIN`, `SUPPORT` | Assign a user to a ticket              |
| `DELETE` | `/api/v1/tickets/{id}/assignments/{assigneeId}` | `ADMIN`, `SUPPORT` | Unassign a user from a ticket          |
| `PATCH`  | `/api/v1/tickets/{id}/status`                   | `ADMIN`, `SUPPORT` | Update ticket status                   |
| `PATCH`  | `/api/v1/tickets/{id}/priority`                 | `ADMIN`, `SUPPORT` | Update ticket priority                 |
| `PATCH`  | `/api/v1/tickets/{id}/description`              | `ADMIN`, `SUPPORT` | Update ticket description              |
| `GET`    | `/api/v1/tickets/staff/assigned`                | `ADMIN`, `SUPPORT` | Retrieve tickets assigned to staff     |

| `POST`   | `/api/v1/users/{id}/promote`    | `ADMIN`       | Promote a user's role                             |
| `POST`   | `/api/v1/users/{id}/demote`     | `ADMIN`       | Demote a user's role                              |
| `GET`    | `/api/v1/users`                 | `ADMIN`       | Retrieve list of all users                        |
| `GET`    | `/api/v1/users/staff`           | `ADMIN`       | Retrieve list of staff users                      |
| `GET`    | `/api/v1/users/{id}`            | `ADMIN`       | Retrieve user details by ID                       |
